# 多开账号与重连系统

## 1. 账号数据

前端“玩家管理”页面现在可添加/编辑/删除游戏账号。

数据库字段包含：

- 登录账号
- 游戏密码密文
- 游戏 EXE
- 窗口标题
- 启动参数
- 自动登录
- 自动重连
- 最大重连次数
- 最大备用账号切换次数
- 重连间隔
- 备用账号列表

## 2. 密码安全

密码使用 `cryptography.fernet.Fernet` 加密后写入 MySQL。

生产环境必须设置：

```text
MHXY_CREDENTIAL_KEY=<Fernet key>
DJANGO_SECRET_KEY=<随机 Django secret>
```

生成 Fernet 密钥：

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

API 永远不返回密码明文，只返回 `has_password`。

## 3. MySQL

生产环境：

```text
DB_ENGINE=mysql
DB_NAME=mhxy_ai
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_HOST=127.0.0.1
DB_PORT=3306
```

然后安装：

```bash
pip install -r requirements.txt
pip install -r requirements-mysql.txt
python manage.py migrate
```

## 4. 多开掉线检测

接口：

```text
POST /api/multibox/health/
```

不传 `account_ids` 时检查所有启用账号；也可以：

```json
{"account_ids":[1,2,3,4,5]}
```

健康检查通过 `FindWindow/窗口句柄` 判断客户端是否存在。任一账号异常，队伍返回：

```text
PAUSE
```

避免其他账号继续执行任务。

## 5. 重连策略

默认：

```text
掉线
 ↓
第1次重连
 ↓
第2次重连
 ↓
第3次重连
 ↓
仍失败
 ↓
备用账号1
 ↓
继续重连
 ↓
备用账号2
 ↓
全部失败 → FAILED
```

每个 `tick()` 只执行一个恢复动作，不在 Web 请求内无限循环。

## 6. 备用账号

例如：

```text
主账号 A
 ├── 备用 B
 └── 备用 C
```

实际运行时先恢复 A；达到重连上限后停止 A，再启动 B。B 仍失败时继续按配置切换 C。

## 7. 重要说明

当前版本已经完成“窗口掉线检测 + 重连策略 + 备用账号切换”的后端编排，但实际游戏登录界面中的账号输入、验证码、二次验证等仍由后续登录 Skill/Executor 实现。

因此现在不会伪造“已经登录成功”。启动客户端成功只代表恢复动作已提交，下一次健康检查必须重新发现有效游戏窗口后才视为恢复。
