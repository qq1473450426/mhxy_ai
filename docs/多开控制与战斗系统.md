# 多开控制与战斗系统

本阶段将项目从“账号启动”升级为“运行控制层”。

## 1. 单开 / 多开

`POST /api/accounts/control/`

### 单开

```json
{"action":"start","mode":"single","account_ids":[1,2,3]}
```

只启动第一个启用账号。

### 多开

```json
{"action":"start","mode":"multi","account_ids":[1,2,3,4,5],"columns":2,"width":960,"height":540}
```

按账号优先级启动多个客户端，并生成窗口排列计划。窗口尚未创建时会返回 `WAITING_WINDOW`，客户端窗口出现后再次调用 `arrange` 即可完成排列。

## 2. 角色选择

`character_slot` 默认 `1`，即登录后默认选择第一个角色。

前端可以单独设置：

- 角色槽位
- 角色定位
- 队伍优先级
- 是否队长

如果角色定位为空，则使用推荐 Skill：

`辅助 → 输出 → 输出 → 输出 → 输出`

用户手工设置优先于推荐。

## 3. 剧情与自动战斗

账号级配置：

- `auto_story_skip`：剧情跳过开关
- `auto_battle`：自动战斗开关
- `battle_template`：任务战斗模板
- `equipment_policy`：装备选择策略

真正执行前仍必须通过 Perception 验证当前页面/战斗状态，不能仅凭计时器点击。

## 4. 战斗模板

当前提供：

- 普通任务战斗
- 抓鬼
- 副本小怪
- 副本首领

模板只描述战斗策略和停止条件；实际输入由 Automation Executor 执行。

## 5. 装备

`BEST_COMBAT` 表示优先穿戴当前等级允许使用、且有效战斗能力更高的装备，而不是简单按装备等级或市场价格排序。
